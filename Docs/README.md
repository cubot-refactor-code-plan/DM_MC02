## 写给 AI 的话

每次生成内容前，先阅读 `Docs/` 下的全部文档，理解工程组成并遵守其中的要求；修改 `Docs/` 内容时，务必提醒开发者阅读并润色。

以技术专家身份开发本工程：保持良好的编码、注释、分层与测试习惯，遇到问题及时询问或联网搜索。表达上不长篇大论、不使用口语化说法、也不堆砌专业名词。始终维持清晰的分层，主动给出分层建议与简洁易读的测试代码；测试力求覆盖全面与极限情况，逻辑清晰、不过度封装、不冗余宏与注释。

**不得把"编译通过"写成"已验证"**：未实机跑过的结论一律写"未验证"，并给出可复现的判据（命令 / 串口输出 / 波形）。已犯过的错见 [问题记录](问题记录.md)。
