## 环境要求

- `cmake`、`ninja`、`arm-none-eabi-gcc`、`arm-none-eabi-gdb` 需在 `PATH` 中。
- CMSIS-DAP 链路需要 `openocd`，并将探针经 SWD 接到目标板。
- VS Code 图形化调试需要 Cortex-Debug；代码索引建议安装 clangd；任务按钮插件可选。
- J-Link 烧写需要 OpenOCD 带 `jlink` / libjaylink 适配器；用 Ozone 或 J-Link GDB Server 调试仍需安装 SEGGER J-Link Software。
- 脚本与 `.vscode/launch.json` 通过工作区目录名寻找 ELF，因此工作区目录名、CMake 工程名与输出文件名应保持 `DM_MC02`；重命名工程时需同步修改这些配置。

## 命令行用法（Linux）

首次配置并编译：

```bash
cmake --preset Debug
cmake --build --preset Debug
```

后续仅编译：

```bash
cmake --build build/Debug
```

使用 CMSIS-DAP 烧写（脚本分别烧写内部 HEX 与外置 USB XIP BIN，并执行校验和复位）：

```bash
./Flash/OpenOCD_flash.sh
```

使用 J-Link 探针烧写（经 OpenOCD `jlink` 适配器；当前环境未连接 J-Link 探针）：

```bash
./Flash/JLink_flash.sh
```

## VS Code 用法

- `Terminal: Run Task` 中可运行 `Configure`、`Build`、`Clean_Rebuild`、`Clean`，以及 Linux / Windows 的 OpenOCD、J-Link 烧写任务；默认构建任务 `Build` 可用 `Ctrl+Shift+B` 运行。
- 在“运行和调试”中选择 `cmsis-dap-debug`，即可通过 OpenOCD 启动 Cortex-Debug，会装载 `build/Debug/DM_MC02.elf` 并运行至 `main`。
- `jlink-debug` 配置已存在，但需先安装 SEGGER J-Link 软件，当前环境未实测。
- Cortex-Debug 可查看变量、寄存器、内存和基本的 FreeRTOS 运行信息；外设寄存器描述文件位于 `Flash/STM32H723.svd`。
- `Flash/linux.jdebug` 是 Ozone 工程示例，内含创建者机器的绝对路径、探针序列号与 Ozone 版本信息；换机器后必须在 Ozone 中重新选择 ELF 与探针，不能视为通用配置。

相关配置文件：`.vscode/tasks.json`、`.vscode/launch.json`、`Flash/daplink.cfg`、`Flash/README.md`。
