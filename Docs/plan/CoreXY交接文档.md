## 3. 硬件与协议事实（实测/手册）

### 3.1 机构

| 项 | 值 |
| --- | --- |
| 一圈行程 | 40 mm（2GT 节距 2 mm × 20 齿） |
| 指令单位 | 80 脉冲/mm（3200 脉冲/圈） |
| 反馈单位 | 1638.4 counts/mm（65536 counts/圈） |
| 换算 | 1 脉冲 = 20.48 counts |
| 正解 | `X = -(c1 - c2) / 3276.8`，`Y = -(c1 + c2) / 3276.8` |
| 逆解 | `p1 = -80·(X + Y)`，`p2 = +80·(X - Y)` |
| 45° 段 | **只有一台电机动**（另一台 delta = 0，不下发子命令） |
| 轴向段（纯 X 或纯 Y） | **两台都动** |

方向实测（用户 627 提供）：向上 → 1 号逆时针、2 号逆时针；向右 → 1 逆 2 顺；右上 → 1 逆。

### 3.2 总线

| 项 | 值 |
| --- | --- |
| 电机总线 | USART2 + RS485（硬件 DE = PD4），115200 8N1 |
| 上位机串口 | USART1（`bsp_uart1`），PA9 TX / PA10 RX，115200 8N1 |
| 单帧时长 | 13 B ≈ 1.13 ms；`0x36` 请求 3 B ≈ 0.26 ms；应答 8 B ≈ 0.69 ms；MMCL 两台 31 B ≈ 2.7 ms |

### 3.3 帧格式

```
单机：addr FUNC payload... 6B
MMCL：target(0x00) AA lenH lenL <子命令1><子命令2>... 6B        len = payload + 5
0xFD 位置：addr FD dir rpmH rpmL accel p0 p1 p2 p3 raF sync 6B   （13 B，相对模式脉冲写正幅值，方向走 dir）
0x36 应答：addr 36 sign v3 v2 v1 v0 6B                          （8 B）
```

实测证明格式正确（2026-10-23 dump）：

```
00 AA 00 1F
  01 FD 01 01 2C E6 00 00 0F A6 00 00 6B    ← 电机 1，dir=1，300 rpm，acc=230，4006 脉冲
  02 FD 00 01 2C E6 00 00 0F A0 00 00 6B    ← 电机 2，dir=0，300 rpm，acc=230，4000 脉冲
6B
```

长度 31 = 26 + 5，两条子命令各 13 B 且各带 `6B`，与官方 `Emm_V5_Multi_Motor_Cmd()` 一致。

### 3.4 关键时序常数

| 名称 | 值 | 含义 |
| --- | --- | --- |
| `SEND_GAP_MS` | 5 | 两帧之间的最小间隔 |
| `SEND_QUIET_MS` | 20 | 发任何控制命令前的总线静默（等上一条 `0x36` 应答收完） |
| `ENABLE_GAP_MS` | 20 | 两台使能/失能帧之间的间隔 |
| `ARRIVE_CONFIRM` | 2 | 连续多少拍满足到位才发下一段（**已被人为改成 6 再改回 2**） |
| `OVERRUN_MM` | 3.0 | 段内超出预期行程多少 mm 停机（轴级保护 + 包围盒容差） |
| `ZERO_TOL_MM` / `ZERO_CONFIRM` | 0.5 / 3 | 原点复核窗口与确认拍数 |
| 轮询 | 10 ms 一拍，两台交替 → 每台 20 ms 刷新一次 |
| 命令后 hold | 30 ms 不发查询 |

**减速时间估算（重要）**：`(256 − acc) × 50 µs / RPM`。`acc=230`、300 RPM → 加速/减速各约 **390 ms**。

## 7. 最新现场数据（2026-10-23，当前固件）

```
home → en 1 → m 100 50
[CXY] cmd 0x02 -> st=0
[CXY] fault st=2 pos=(50.01, 50.00)
[CXY] mmcl(18): 00 AA 00 12 01 FD 01 01 2C E6 00 00 1F 40 00 00 6B 6B
[CXY] online 1=0 2=1
[CXY] pos=(50.00, 50.00) c1=-163850 c2=2 state=2 err=2 origin=1
```

判读：

- `m 100 50` 应拆成 `seg0 = (50,50)`（45°，仅电机 1，−8000 脉冲）+ `seg1 = (100,50)`（轴向 X，两台各 4000/4008 脉冲）。
- 最后一条 MMCL 是 **18 字节、只有一条子命令** → 那是 seg0；**seg1 从未发出**。
- `c1 = -163850`（seg0 目标 −163840，差 10）、`c2 = 2`（目标 0）→ **`in_window` 成立**。
- 所以 `arrived` 不成立的原因是 `_settled`（本版新加的停稳判据），或 `fresh_ok`。

更早一版（`ARRIVE_CONFIRM=6`、无 `_settled`）的数据：

```
m 100 50 → fault st=2 pos=(75.06, 25.06)
pos      → (100.02, 50.03)  c1=-245838  c2=81906
```

→ seg0 正常，**seg1 只有电机 2 执行**（c2 走到目标 +81920），电机 1 停在 seg0 终点，随后才补上。反解 `c1=−164102, c2=+81855` 恰好给出 `(75.06, 25.06)`，与打印一致。

## 8. 下一步建议（按优先级）

1. **先确认 `_settled` 是否成立**：在 `pos` 或 `dump` 里打印 `_settled[0] / _settled[1] / _fresh[0] / _fresh[1] / _arrive_ok`。
   - 若 `_settled` 恒为假 → 编码器静止抖动大于 9 counts，放宽或改用"固定延时"。
   - 若 `_settled` 为真但 `arrived` 仍为假 → 检查 `_fresh`（某台 `0x36` 应答是否真的收到）。
2. **若确认是"seg1 被驱动器排队"**：说明第一段命令在驱动器里还没执行完。可用最直接的办法——`arrived` 成立后再固定等 `减速时间 + 余量`（按 `(256−acc)×50 µs×rpm` 算，`acc=230/300 rpm` 约 400 ms）再发第二段。
3. **不要**再改：MMCL 组帧、`_cmd_target` 的绝对坐标换算、`arrived` 的"两台回复 + 窗口"主体判据——这些是用户验证过的。
4. 修好后把 `Online` 的超时从 30 ms 调到 100 ms（`device_emmv5_group` 里 `_motor[i].online` 的构造参数），否则 `dump` 的 online 显示会持续误导。

## 10. 我的错误清单（供接手者避坑）

1. **把 MMCL 拆成两帧**，理由是"双子命令只有一台执行"——但根因在时序，用户从 694/871/1107 三次要求 MMCL 一起发。
2. **擅自改到位目标为增量式**，破坏了原本可用的绝对坐标判据。
3. **反复引入新的"停稳"判据**（两拍比较 → 时间戳 → 差值），每次都换一种实现，没有先用数据验证。
4. **在同一轮里同时改多处**，导致无法定位是哪一处引入的问题。
5. **只看编译通过就往下走**，未在每步实机确认。
6. 把 `Online` 的 30 ms 阈值误判当成"电机掉线"，误导了排查方向。

## 11. 2026-10-23 第二次改动（分段时序按用户实测协议重做）

用户给出的总线时序（原话）：MMCL 发出后**不能紧跟着 read**，要隔 **5 ms** 才开始第一次
read；等到 read1、read2 返回的位置**都是电机到位**，再等 **5 ms** 发下一条 MMCL，之后同样
的 read 流程。另外明确：**到位帧（`FD 9F`）不开**，只用 `0x36` 读回的位置判到位。

| # | 改动 | 位置 |
| --- | --- | --- |
| 1 | 删除 `_settled` / `SETTLE_COUNTS` 停稳判据 | `corexy.cpp` `update()` |
| 2 | 删除交替轮询（`_poll` / `_fresh` / `_poll_hold`），改成**成对读位置**：`_read_position()` 一问一答（发 `0x36` → 最多等 `REPLY_TIMEOUT_MS`=10 ms 收应答），读 1 → 隔 `SEND_GAP_MS`(5 ms) → 读 2 | `update()` / `_read_position()` |
| 3 | MMCL 发出后 `_read_hold = +READ_GAP_MS`(5 ms)，到位后直接发下一段（`_send_segment` 内部先静默 `SEND_QUIET_MS`=20 ms） | `_send_segment()` |
| 4 | 到位 = 这一拍两台都读到应答（`read_ok`）且都落在 `arrive_tol` 窗口内，连续 `ARRIVE_CONFIRM`=2 拍 | `update()` |
