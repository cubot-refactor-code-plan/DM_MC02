# CoreXY 运动控制要点与避坑

> 对象：`User/Module/corexy.*` + `User/Device/device_emmv5_group.*` + `User/Protocol/emmv5_protocol.*`
> 机构：两台 Emm_V5 闭环步进，一路 RS485（USART2，115200 8N1，DE = PD4），地址 1、2。
> 本文只写**改代码前必须知道的约束**和**踩过的坑**；接口细节见 `User/Module/corexy.md`。

---

## 0. 三十秒版本

```text
一条 MMCL 总帧（两台的子命令在同一帧；某台不动就不发它的子命令）
   ↓ 5 ms，不许读
读 1（发 0x36 → 等应答）→ 5 ms → 读 2（发 0x36 → 等应答）
   ↓
两台读回的位置都在 arrive_tol 内，连续 2 拍成立 = 这一段到位
   ↓
还有下一段就再发一条 MMCL，同样走 5 ms → 读两台
```

八条硬约束：

1. **MMCL 两台一起发**，不要拆成两帧；
2. **发完命令 5 ms 内不许 read**；
3. **读位置一问一答**，两条查询之间隔 5 ms；
4. 到位要**本拍两台的真实读数**，不是“曾经收到过”；
5. **不用到位帧 `FD 9F`**（驱动器该回报默认不开），只看 `0x36` 位置；
6. 增量基准用**实测 counts**，不是上一次的指令目标；
7. 路径**拆段**：先 45°（或轴向）到中转点，到位后再轴向到目标；
8. 单段超时给**非常大**（300 s），宁可等也不要误判 `TIMEOUT`。

## 1. 机构、单位与换算

| 项 | 值 | 说明 |
| --- | --- | --- |
| 一圈行程 | 40 mm | 2GT 节距 2 mm × 20 齿 |
| 指令单位 | 80 脉冲/mm | 3200 脉冲/圈（16 细分） |
| 反馈单位 | 1638.4 counts/mm | 65536 counts/圈 |
| 比例 | 1 脉冲 = 20.48 counts | 发送与判定**单位不同**，混用会“只走 1/N”或“永远到不了” |

```text
正解   X = -(c1 - c2) / (2 × 1638.4)      c1、c2 = 两台 0x36 读数
      Y = -(c1 + c2) / (2 × 1638.4)

逆解   p1 = -80 × (X + Y)                 p1、p2 = 两台目标脉冲
      p2 = +80 × (X - Y)
```

| 世界方向 | 电机 1 | 电机 2 |
| --- | --- | --- |
| `+X` | ↓ | ↑ |
| `+Y` | ↓ | ↓ |
| `+X +Y`（45°） | ↓↓ | 不动 |
| `+X -Y`（45°） | 不动 | ↑↑ |
| `-X -Y`（45°） | ↑↑ | 不动 |
| `-X +Y`（45°） | 不动 | ↓↓ |

即：**轴向两台同时动，45° 对角只动一台**。核对用控制台 `g <0..7> [mm]`。

## 2. 总线时序（最容易出错的地方）

### 2.1 事实

| 事实 | 后果 |
| --- | --- |
| RS485 半双工 | 同一时刻只允许一个方向传输，**一次只能有一条查询在途** |
| 控制命令（`0xFD`/`0xF1`/`0xFC`/`0x0A`/`0xFE`）**没有应答** | 发出去就没反馈，丢帧只能靠“动作没发生”反推 |
| 只有 `0x36`（位置）/ `0x3A`（状态）有应答 | 到位判断只能靠它们 |
| `Uart::send()` 只是入队，DMA 会把两帧连成一串 | 连续发帧之间必须留真实延时 |

线上时间（115200，8N1）：`0x36` 请求 3 B ≈ 0.26 ms，应答 8 B ≈ 0.69 ms，
两台 MMCL 31 B ≈ 2.7 ms。

### 2.2 时序常数（`corexy.hpp`）

| 常数 | 值 | 用在哪 |
| --- | --- | --- |
| `READ_GAP_MS` | 5 ms | MMCL 发出后到第一次读；两条查询之间 |
| `READ_PERIOD_MS` | 10 ms | 两次「读两台」之间的间隔 |
| `REPLY_TIMEOUT_MS` | 10 ms | 单台 `0x36` 应答等待上限 |
| `SEND_GAP_MS` | 5 ms | 连续帧之间（停止/清零/使能） |
| `SEND_QUIET_MS` | 20 ms | 发**无应答命令**前的总线静默 |
| `ENABLE_GAP_MS` | 20 ms | 两台使能/失能帧之间 |
| `ARRIVE_CONFIRM` | 2 拍 | 连续多少拍两台都在窗口内才算到位 |
| `SEG_TIMEOUT_MS` | 300000 ms | 单段超时 |

### 2.3 三段时序

```text
发命令前（使能 / 失能 / 清零 / 停止 / 直发 0xF1·0xFC）
  静默 SEND_QUIET_MS = 20 ms（期间一条查询都不发）
  帧间 SEND_GAP_MS = 5 ms（使能帧之间 20 ms）

发 MMCL
  _read_hold = now + READ_GAP_MS = 5 ms

读位置（每拍一次，_read_hold 之后）
  请求 addr1 36 → 等应答（≤ 10 ms）
  SEND_GAP_MS = 5 ms
  请求 addr2 36 → 等应答（≤ 10 ms）
  _read_hold = now + READ_PERIOD_MS = 10 ms
```

违反后果（实测）：

- MMCL 后紧跟 read → 驱动器正在回 `0x36`，收不进命令，**整帧被丢**，表现为“命令不执行”；
- 两台背靠背读 → 后一条请求吃掉前一台的应答，那一台永远拿不到新读数；
- 无应答命令不静默 → 只有一台失能 / 清零丢一帧导致零位偏移。

## 3. 位置命令怎么发

1. **一条 MMCL 总帧**带两台子命令（`00 AA lenH lenL …sub1… …sub2… 6B`），不拆成两帧；
2. 子命令用**相对模式 + 方向字节 + 正幅值**：`raF = 0`，方向走 `dir`，幅值永远是 `|Δp|`；
   **绝不把负数写进无符号字段**（会被当成 42 亿脉冲，电机会一直冲）；
3. 相对模式的基准是“上一次输入目标”，所以增量必须用**实测 counts** 反算：

```text
now_pulse = round(当前实测 counts / 20.48)
delta     = 本段目标脉冲 - now_pulse
```

4. 速度按脉冲数分摊，保证两台同时到达；`acc` 两台相同：

```text
maxΔp = max(|Δp1|, |Δp2|)
rpm_i = clamp(rpm × |Δp_i| / maxΔp, 1, 5000)
```

5. `|Δp_i| == 0` 的电机**不发子命令**（45° 段因此通常只有一条子命令，帧长 18 B；
   两台的帧长 31 B，`dump` 可用来判断当前这条帧是单台还是两台）。

## 4. 怎么判到位

```text
到位 = 本拍两台都读到了应答（read_ok）
       且 |c1 - 目标1| ≤ arrive_tol × 1638.4
       且 |c2 - 目标2| ≤ arrive_tol × 1638.4
       连续 ARRIVE_CONFIRM = 2 拍成立
```

- **不动的电机也要读**：45° 段只有一台动，另一台“停在原地”同样是执行成功的证据；
  不读它，单台丢应答/掉线也能判通过。
- **目标 = 段起点实测 counts + 本段增量 counts**，不要用“世界坐标 × 1638.4”当绝对目标：
  编码器零位和软件原点只要差一个常数，绝对目标就永远对不上，会一直等到超时。
- **不要用驱动器的到位帧 `FD 9F`**：该回报默认不开，判到位只看 `0x36` 读回的位置。
- **必须连续 2 拍**：0.2 mm 窗口在减速尾巴上就会成立（约还剩 30 ms），单拍就发下一段，
  新命令会叠在未完成的运动上 → 两轴失步 / 贴边 `BAD_ARG`。

## 5. 路径拆解

`move_to(p)` 以当前**实测**坐标 `(x0, y0)` 为起点：

```text
dx = p.x - x0, dy = p.y - y0

dx == 0 或 dy == 0 或 |dx| == |dy|   → 单段直达
其余                              → d = min(|dx|, |dy|)
                                    段 1：(x0 ± d, y0 ± d)   ← 45°，通常只动一台
                                    段 2：p                  ← 轴向，两台都动
```

例：`m 100 50`（起点 `0,0`）→ 段 1 到 `50,50`，段 2 到 `100,50`。

- 每段发一条 MMCL，**这一段确认到位后才发下一段**；
- 安全限位是凸矩形，起点和目标都在内 ⇒ 45° 中转点必在内，不需要单独校验中转点；
- 控制台 `pos` 的 `seg=当前段/总段数` 可以直接看到走到第几段；
- 拆段带来一次“减速—再加速”的停顿（约 40~60 ms + 帧间隔），属于预期代价。

## 6. 限位与安全

| 名称 | 作用 | 当前值 |
| --- | --- | --- |
| `theory` | 机械真实行程，运动**过程中**越界即停机 | `(0,0) ~ (190,200)` |
| `safe` | 允许作为**运动目标**的范围 | `(1,1) ~ (189,199)` |

- `move_to` / `move_by` / `step` 只按 `safe` 校验，越界返回 `BAD_ARG`；
- 过程中有两层保护：世界坐标越出 `theory ± OVERRUN_MM(3 mm)`，以及单轴行程
  `_seg_travel ± OVERRUN_MM`，任一触发就广播停止并进 `Fault`；
- **保护容差不能用 `arrive_tol`**（0.2 mm）：正常减速过冲就有 1 mm 量级，贴着 `y=0` 的段会被误杀；
- 上电 `zero_here()` 即把当前位置记为 `(0,0)`；清零命令无应答，必须靠读数复核
  （连续 3 拍在 ±0.5 mm 内才置 `origin_verified()`）。未复核时 `move_to` 返回 `NOT_INIT`。

## 7. 状态机与超时

| 状态 | 含义 | 转移 |
| --- | --- | --- |
| `Idle` | 没有待走的段 | `move_*` → `Moving` |
| `Moving` | 执行当前段 | 两台到位 → 下一段 / `Idle`；超时 / 越界 → `Fault` |
| `Fault` | 已停机 | **只能 `stop()` 清除**（`Fault` 下 `move_to` 返回 `BAD_ARG`） |

- 单段超时是**常量 300 s**，不按行程估算：行程短、速度低、加速时间长的组合很容易被
  算短的估算值误杀；
- 超时只兜底（堵转、掉线、目标被限幅）；真要中断请用 `stop`。

## 8. 排障：现象 → 根因 → 处理

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 命令返回 OK 但电机不动，最后 `FAULT TIMEOUT` | 驱动器没使能 / MMCL 被在途 `0x36` 应答吃掉 | 先 `en 1`；发命令前静默 20 ms |
| 电机一直冲、只能断电 | 绝对模式写了负目标 | 相对模式 + 方向字节 + 正幅值 |
| 只走了 1/N 的距离 | 把指令脉冲当成反馈 counts | 判定用 counts（×20.48） |
| 第一段能走、第二段不执行 | 到位那一拍刚发 `0x36`，0 ms 后又发 MMCL | MMCL 后 5 ms 再读 |
| 同一个 MMCL 里只有一台电机先动，中途 `pos` 出现 `(75,25)` 这类中间态 | 上一段没停稳就发了下一段，子命令被驱动排队 | 到位判据要“本拍两台读数 + 连续 2 拍” |
| 两轴失步、贴边 `BAD_ARG` | 减速段末尾被当成到位 | 同上（`ARRIVE_CONFIRM`），保护容差用 `OVERRUN_MM` |
| 只有一台失能 / 位置到了却 `TIMEOUT` | 无应答命令前没静默，帧被吃掉 | 统一 `_quiet()` + 增量式到位目标 |
| `pos` 的 `c1/c2` 与实物差一个常数 | 清零命令丢帧 | 复核 `origin=1`；目标用增量不用绝对 |
| 移动中 `pos` 不动 | 该拍没读到位置（应答超时） | 看串口/接线；`_read_position` 有 10 ms 上限 |

## 9. 改代码前的检查清单

- [ ] 新增的 `send()` 前是否静默了 20 ms（无应答命令）？
- [ ] 新增的连续帧之间是否留了 5 ms？
- [ ] 是否有“发完命令立刻读”的地方？应该是 5 ms 后、一问一答。
- [ ] 是否把两台子命令拆成了两帧？（不允许，必须一条 MMCL）
- [ ] 是否往无符号字段写了负数？（不允许）
- [ ] 增量基准是否取**实测** counts？
- [ ] 到位判据是否同时要求两台、且是本拍读数？
- [ ] 是否引用了到位帧 `FD 9F`？（不允许，未开启）
