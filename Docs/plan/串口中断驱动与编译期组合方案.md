# 串口中断驱动与编译期组合方案

> 适用：`User/Bsp/bsp_uart`、`User/Bsp/bsp_cfg`、`User/Device` 设备驱动与 `device_cfg`。
> 目标：在 C++11 下同时支持 DMA 与中断两种串口收发方式，保持 `Config`、流缓冲区与公开接口一致；设备按编译期类型组合，不引入虚函数、函数指针表与类型擦除。

## 1. 结论

把现有 `BspUart` 的底层收发调用收敛为 Transport 策略，形成 `BspUartT<Transport, RX_SIZE, TX_SIZE>`。`bsp_cfg` 直接用 `BspUartT<...>` 声明全部串口实例；设备类改为模板，`device_cfg` 用 `decltype` 绑定具体串口实例。这样 RX/TX 流缓冲区大小成为串口类型的一部分，设备只依赖 `send()` / `receive()` 等公开接口，切换串口时不需要改设备实现。

该方案只使用类模板、别名模板、显式实例化与 `decltype`，C++11 即可落地；运行时没有新增间接跳转，RAM 与 Flash 用量可按实例数静态估算。

## 2. 分层与文件职责

| 文件 | 职责 |
| --- | --- |
| `User/Bsp/bsp_uart.hpp` | `BspUartT<Transport, RX_SIZE, TX_SIZE>`、`DmaTransport`、`ItTransport`、诊断结构与公开接口 |
| `User/Bsp/bsp_uart.cpp` | `BspUartT` 实现、显式实例化、HAL 回调按句柄分发 |
| `User/Bsp/bsp_cfg.hpp` | `BspUartT<Transport, RX, TX>` 串口实例 `extern` |
| `User/Bsp/bsp_cfg.cpp` | 串口实例定义与 `bsp_init()` |
| `User/Device/device_r9ds.hpp/.cpp` | `DeviceR9dsT<Uart>`，SBUS 帧解析与帧格式校验 |
| `User/Device/device_emmv5*.hpp/.cpp` | `DeviceEmmv5T<Uart>` 等设备模板 |
| `User/Device/device_cfg.hpp/.cpp` | 用 `decltype` 绑定设备与串口实例 |
| `User/App/task/sys_task.cpp` | DMA 串口巡检与 IT 串口恢复调用 |

依赖方向保持 `Device → Bsp`。设备头文件只依赖 `bsp_uart.hpp` 的模板接口，不包含 `bsp_cfg.hpp`；`device_cfg` 负责把具体实例交给设备模板。

## 3. 串口类型与配置

`BspUartT` 的公开接口与现有 `BspUart` 对齐：

```cpp
template <typename Transport, size_t RX_SIZE, size_t TX_SIZE>
class BspUartT
{
public:
  struct Config
  {
    Config(UART_HandleTypeDef *huart = nullptr,
           UartMode mode = UartMode::TxRx,
           uint32_t baudrate = 115200U);

    UART_HandleTypeDef *huart;
    UartMode            mode;
    uint32_t            baudrate;
  };

  Status init();
  Status send(const uint8_t *data, size_t size,
              uint32_t timeout_ms = portMAX_DELAY,
              size_t *written = nullptr);
  Status receive(uint8_t *buffer, size_t size,
                 uint32_t timeout_ms = portMAX_DELAY,
                 size_t *received = nullptr);
  Status printf(const char *fmt, ...);

  bool tx_recover();
  bool rx_recover();

  void on_idle_isr(uint16_t size, BaseType_t *woken);
  void start_transmission_from_isr(BaseType_t *woken);
  void on_error_isr();

  size_t get_tx_free_space();
  size_t get_rx_available_data();

  RxHealth rx_health() const;
  RxDiag   rx_diag() const;
  TxDiag   tx_diag() const;
};
```

`bsp_cfg.hpp` 定义别名并声明实例：

```cpp
extern BspUartT<uart_detail::DmaTransport, 128, 128> bsp_uart1;
extern BspUartT<uart_detail::DmaTransport, 128, 128> bsp_uart2;
extern BspUartT<uart_detail::DmaTransport, 128, 128> bsp_uart3;
extern BspUartT<uart_detail::DmaTransport, 128, 128> bsp_uart4;
extern BspUartT<uart_detail::DmaTransport, 128, 128> bsp_uart7;
extern BspUartT<uart_detail::DmaTransport, 128, 128> bsp_uart8;
extern BspUartT<uart_detail::DmaTransport, 128, 128> bsp_uart9;
extern BspUartT<uart_detail::DmaTransport, 128, 128> bsp_uart10;

extern BspUartT<uart_detail::ItTransport, 128, 32> bsp_uart_it5;
```

`bsp_cfg.cpp` 中对应定义为：

```cpp
BspUartT<uart_detail::DmaTransport, 128, 128> bsp_uart1({&huart1, UartMode::TxRx, 115200U});
BspUartT<uart_detail::ItTransport,  128, 32>  bsp_uart_it5({&huart5, UartMode::RxOnly, 100000U});
```

`RX_SIZE` 与 `TX_SIZE` 只影响该串口实例的流缓冲区与暂存区，设备模板不感知这两个值。

## 4. DMA 与中断的差异收敛

两个 Transport 只封装底层 HAL 调用与状态查询：

| 操作 | `DmaTransport` | `ItTransport` |
| --- | --- | --- |
| 启动接收 | `HAL_UARTEx_ReceiveToIdle_DMA()` | `HAL_UARTEx_ReceiveToIdle_IT()` |
| 启动发送 | `HAL_UART_Transmit_DMA()` | `HAL_UART_Transmit_IT()` |
| RX 健康检查 | `RxState`、`CR3.DMAR`、DMA EN | `RxState`、`CR1.RXNEIE`、`CR1.IDLEIE` |
| TX 已发字节 | DMA 剩余计数 | `huart->TxXferCount` |
| 中止通道 | `HAL_UART_AbortReceive/Transmit()` | 相同 |

流缓冲区、`_tx_lock`、`_printf_lock`、发送回滚、诊断计数与恢复流程仍留在 `BspUartT` 内，只通过 Transport 调用底层差异部分。

HAL 回调继续放在 `bsp_uart.cpp`，按 `huart` 分发到具体实例。该层是 HAL 的固有边界，不参与设备逻辑。

## 5. 设备与配置层

设备类只依赖串口公开接口：

```cpp
template <typename Uart>
class DeviceR9dsT
{
public:
  explicit DeviceR9dsT(Uart &uart) : _uart(uart) {}

  Status init();
  void update();

private:
  Uart &_uart;
};
```

`device_cfg.hpp` 用 `decltype` 绑定实例，不额外建立设备类型别名：

```cpp
#include "bsp_cfg.hpp"
#include "device_r9ds.hpp"

// 等价于：extern DeviceR9dsT<BspUartT<uart_detail::ItTransport, 128, 32>> r9ds;
extern DeviceR9dsT<decltype(bsp_uart_it5)> r9ds;
```

`device_cfg.cpp` 中的定义与头文件保持一致：

```cpp
DeviceR9dsT<decltype(bsp_uart_it5)> r9ds(bsp_uart_it5);
```

`decltype(bsp_uart_it5)` 需要在 `device_cfg.hpp` 中看到 `bsp_uart_it5` 的声明，因此该头文件包含 `bsp_cfg.hpp`。`bsp_cfg.hpp` 不反向包含 `device_cfg.hpp`，依赖方向不形成环。

SBUS 的 100000 / 9B / 偶校验 / 2 停止位校验从串口驱动移到 `DeviceR9dsT::init()`。`BspUartT<ItTransport>` 只负责字节流收发，不内置任何协议参数。

## 7. 实施顺序

1. 在 `bsp_uart` 中引入 `BspUartT` 与两个 Transport，保持 `BspUart` 原有 DMA 行为；在 `bsp_cfg` 中声明实例，编译并确认现有 DMA 串口不受影响。
2. 增加 `ItTransport`，把 UART5 从 `BspSbus` 切换到 `BspUartT<uart_detail::ItTransport, 128, 32>`；`DeviceR9dsT` 改接新类型，SBUS 参数校验移入设备层，运行 R9DS 自检。
3. 将 EMMV5 单机与多机设备模板化，`device_cfg` 使用 `decltype` 绑定串口实例；删除设备层对具体串口类型的硬编码。
4. 删除 `BspSbus`，更新文档，执行回环、R9DS 与现有 DMA 串口回归测试。

## 8. 验证

编译验证使用现有 `shell: Build`（`cmake --build --preset Debug`）。R9DS 验证把 `APP_TEST_R9DS_ENABLED` 置 1，观察 `byte`、`frame` 持续增长且 `on=1 fs=0`；UART5 回环验证将 PC12 与 PD2 短接，按 100000 / 9B / 偶校验 / 2 停止位收发 25 字节并比对内容。

`tx_diag()` 与 `rx_diag()` 在正常运行时除 `init` 首次启动外应保持为 0；若 `drop_bytes`、`start_fail_cnt` 或 `recover` 计数持续增长，应先检查中断优先级、流缓冲区容量与 TX 缓冲区生命周期。USART2 RS485 继续使用 `BspUart`，本次不改其硬件 DE 配置。

## 9. 边界

`ItTransport` 的 TX/RX 均为逐字节中断，适合 SBUS、115200 调试口等低速或小包场景；921600 的 EMMV5 继续使用 `BspUart` 的 DMA。若后续新增串口组合，需要在 `bsp_uart.cpp` 中补一条显式实例化与一条 HAL 回调分发分支；这是 HAL 全局回调模型的固定成本。
