# CUBOT 编码风格规范

> 适用范围：`User/` 下的全部代码；基准样板为 `User/Bsp/bsp_uart.{hpp,cpp}`。
> 格式类规则已固化在 `.clang-format`（手动执行格式化）；命名、注释、架构类规则需人工遵守。

---

## 1. 文件组织

| 规则 | 说明 |
|---|---|
| 文件名 | 全小写 + 下划线：`bsp_uart.hpp`、`can_bus.cpp` |
| C++ 头后缀 | `.hpp` |
| C++ 源后缀 | `.cpp` |
| 头文件保护 | `#ifndef __XXX_HPP__` + `#define` + 末尾 `#endif // __XXX_HPP__` |
| 间接包含的头文件 | 行尾加 `// IWYU pragma: keep`，规避 clangd 误报（详见 [../guide/clangd配置.md](../guide/clangd配置.md)） |

C 调 C++ 的转接头见第 6 节，文件说明块的位置见第 3 节。

## 2. 命名规范

| 元素 | 规则 | 示例 |
|---|---|---|
| 类名 / 结构体 / 枚举类型 / 类型别名 | 大驼峰，不加 `_t` 后缀 | `PidConfig`、`PidInput`、`ImuData` |
| 方法 / 自由函数 / 类的全局实例 | 小写蛇形 | `init()`、`start_reception()`、`bsp_init()`、`calc()` |
| 私有成员变量 / 私有函数 | `_` 前缀 + 小写蛇形 | `_huart`、`_rx_stream_buffer`、`_diff_mode` |
| 宏 / 常量 / 枚举值 / 模板参数 | 全大写蛇形 | `MAX_INSTANCES`、`DATA_PACK_MAX_LENGTH` |

例外：

1. 构造函数 / 析构函数必须与类名（大驼峰）一致，如 `BspUart::BspUart()`
2. 外部库（HAL / FreeRTOS / 其他 C 库）强制要求固定名称的回调，如 `HAL_FDCAN_RxFifo0Callback`、`HAL_UART_RxCpltCallback`、`__io_putchar`、`_write`
3. CubeMX 生成的默认任务名（如 `StartDefaultTask`）保留原名，以便 CubeMX 重新生成时同名兼容

## 3. 注释规范（Doxygen）

> **@file 说明块只写在头文件的最顶部；源文件最顶部不放任何说明，直接以 `#include` 开头。**
> 文件说明、@details、@note、使用示例等全部收敛到头文件顶部；源文件内只保留函数/分区级注释。

```cpp
/**
 * @file bsp_uart.hpp
 * @author 名字
 * @brief 一句话说明这个文件是干什么的
 * @version 0.2
 * @date 日期
 *
 * @todo 待办事项
 *
 * @copyright Copyright (c) 2026
 *
 * @details 详细说明 / 使用示例
 *
 * @note 注意事项
 */
```

- **函数注释**：`@brief`（必须）+ `@param` + `@return` + `@note`；公共接口必须写全，私有函数可只写 `@brief` 或行注释
- **注释语言**：中文；描述"为什么"，而不是复述代码。要求作为技术人员对代码进行解释，不要过口语化也不要过专业化。
- 未使用的参数写 `(void)arg;` 并注明

### 分区横幅

源文件与头文件按功能分区，分区用「开始 + 结束」成对的短横线横幅隔开：开始行写分区名，结束行只写短横线。结束行紧贴在下一个分区标题行的上一行，同时充当上一分区的结束与下一分区的开始。

```cpp
// ---------------- 公有接口 ----------------

/** @brief 发送数据（阻塞到写完或超时） */
Status send(const uint8_t *data, size_t size, uint32_t timeout_ms);

// ----------------
// ---------------- ISR 入口 ----------------

extern "C" void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
}

// ----------------
```

- 分区名用中文短语：`构造`、`公有接口`、`ISR 入口`、`私有实现`、`成员变量`
- 类内的分区横幅与类成员保持同级缩进（2 空格），结束行放在类体 `};` 之前
- **分区不可嵌套**：一个文件内所有分区处于同一层级，需要细分就新增同级分区，不要写子分区
- 函数体内不使用横幅，过程说明用普通 `//` 注释

## 4. 类设计模式

1. **全局实例模式**：在 `xxx_cfg.cpp` 中实例化，`xxx_cfg.hpp` 中 `extern` 声明
2. **模板实例化**：模板类定义在 `.hpp`，显式实例化放 `.cpp`（如 `template class BspUart<64>;`）
3. **HAL 中断回调**：统一放在对应 BSP 的 `.cpp` 中，用 `extern "C"` 包裹，通过句柄查表分发
4. **配置结构体统一模式（Config）**：类的初始化 / 构造参数收进类内的 `Config` 结构体（命名固定为 `Config`）；初始化参数少于三个时直接用裸参数。
5. **构造函数只做赋值**：能在类实现处给默认值的就在那里给，能在构造函数传入的就在构造函数传，不能在构造时完成的放到 `init()`。任何 FreeRTOS 操作或需要运行的调用（`xTaskCreate`、`xSemaphoreCreate*`、`snprintf`、`memset`、注册表注册等）一律移入 `init()`，构造函数中只允许成员赋值。
6. **隐藏逻辑必须显式化**：如 `i_max == 0 → 跟随 out_max`，要写在构造函数里并注释
7. **不使用 `friend`**：需要类外访问的成员与构造函数直接设为 `public`或者写出访问接口，不写友元声明

## 5. 分层架构

依赖方向（上层可用下层，禁止反向）：

```
App（应用层，api_xxx 转接）
 └─ Module
     └─ Device（设备层，单设备驱动）
         └─ Bsp（板载支持包，完全不考虑上层硬件细节）
```

- 跨层通信使用下一层暴露的全局实例，不直接操作 HAL

## 6. C/C++ 混编

### 必须加 `extern "C"` 的场合

- HAL / FreeRTOS 回调必须 `extern "C"`，防止名称修饰
- 任务函数若被 FreeRTOS 以 C 方式调用，需要 `extern "C"` 且参数为 `void *pvParameters`

### 转接的粒度

- C 调 C++ 统一通过 `api_xxx.h` 转接，目前只有 `api_main`（`api_main.h` / `api_main.cpp`）
- C 侧不能直接调用 C++ 类：在 `.c` / `.cpp` 中写 `extern "C"` 转接接口，由 C++ 一侧实现
- 整个工程只在 `main.c` 处转接一次：把 main 的内容提取成 `api_main`，中断回调、初始化、主循环都放入其中；FreeRTOS 同理，加 `extern "C"` 即可。HAL 库自身已提供 C++ 调用 C 所需的 `extern "C"`。

## 7. 书写与格式规则

### 由 .clang-format 固化

- 2 空格缩进、Allman 大括号（换行）
- `*` `&` 靠右：`uint8_t *data`
- 连续赋值 / 声明对齐；行尾注释对齐
- 不限制行长（`ColumnLimit: 0`）
- 指针固定靠右（`DerivePointerAlignment: false`）

格式化为**手动执行**，工程里没有自动格式化：在编辑器中对当前文件执行 Format Document，需要批量统一时直接调用 clang-format（命令与工具来源见 [../guide/clangd配置.md](../guide/clangd配置.md)）。

### 需人工遵守

- 使用 `auto` 能显著提升开发效率或可读性时就用，但必须在旁边写注释说明
